# Временный GitLab-стенд — выполнено и удалено

27 октября 2026. По разрешению пользователя использована отдельная VM с лимитом расходов до 50 рублей. Конечная конфигурация: standard-v3, 2 vCPU/100%, 8 GiB RAM, HDD 20 GiB, Ubuntu 24.04 x86_64, зона D. Существующая default-подсеть использована только для чтения; Terraform управлял только VM и отдельной security group. Загрузочный диск auto_delete=true.

Из-за квот 4 vCPU/SSD60 были заменены на указанную конфигурацию. Расчётная цена: 2×1,24 + 8×0,33 + 20×0,0048 + 0,26352 = 5,47952 руб./час активной работы с диском и публичным IPv4. Фактический счёт здесь не приводится. Тарифные источники: https://yandex.cloud/ru/docs/compute/pricing и https://yandex.cloud/ru/docs/vpc/pricing .

GitLab слушал только 127.0.0.1:18080, доступ к веб-интерфейсу шёл через SSH-туннель. SSH22/443 и диагностический ICMP ограничены операторскими /32. Сервисный аккаунт облака в VM не назначался. Временный административный GitLab token после работы отозван.

После сохранения и проверки скриншотов/журналов выполнен Terraform destroy. VM, auto-delete загрузочный диск и отдельная SG удалены; отсутствие VM и диска подтверждено API. Результат — ../evidence/cleanup.txt. Существующие VM, сети и подсети в план удаления не входили.

Для воспроизведения нужны свои folder_id, subnet_id, ssh_public_key, operator_cidrs и авторизация провайдера через YC_TOKEN. Секреты и реальные параметры пользователя не публикуются. main.tf, cloud-init.yaml.tftpl и bootstrap/register-runner скрипты сохраняются как код стенда. Для создания проекта и runner использовался GitLab API; вспомогательный create-lab-access.rb показывает создание краткоживущего токена для GitLab 19 и сохраняет его в отдельный файл с mode0600.

При новом запуске согласовать бюджет, выполнить terraform init/plan, проверить изоляцию ресурсов. После выполнения задания удалить VM с диском; выключение по timer само по себе не прекращает тарификацию диска. Облачная VM вместо VirtualBox/Vagrant явно оговорена в README.
