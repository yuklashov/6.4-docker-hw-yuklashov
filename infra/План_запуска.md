# Отдельный учебный стенд GitLab

Подготовлено 27 октября 2026. Создание отдельной машины разрешено пользователем; денежный лимит ещё не согласован, платный запуск не выполнен.

Конфигурация: обычная непрерываемая VM standard-v3 (Intel Ice Lake), 4 vCPU × 100%, 8 GiB RAM, Ubuntu 24.04 LTS x86_64, network-ssd 60 GiB, динамический публичный IPv4. Используется проверенный публичный Ubuntu-образ fd8a30ptg5tdapq35dlb от 26 октября. Создаются отдельные VPC, подсеть и security group; существующие VM и сети не меняются. Из интернета разрешён только SSH с текущего IPv4 оператора /32. GitLab UI доступен через SSH-туннель. В VM не назначается сервисный аккаунт облака.

## Порядок

1. После согласования лимита: terraform init, plan с текущим folder_id, SSH public key и operator_cidr; проверить, что план создаёт только 4 новых ресурса. Сохранить план локально, не публиковать tfstate/tfplan/tfvars/ключи.
2. Применить сохранённый план, проверить SSH и systemd timer. В cloud-init предусмотрено аварийное выключение через 6 часов с момента загрузки. Это не жёсткий денежный лимит: SSD тарифицируется и в остановленном состоянии.
3. Установить GitLab CE, Docker и Runner, выполнить практику и снять реальные доказательства. Не публиковать пароли/runner authentication token.
4. Сохранить и проверить доказательства локально и на GitHub, отправить отчёт в LMS, проверить подтверждение отправки.
5. Удалить только ресурсы этого Terraform-состояния, включая VM и загрузочный диск; auto_delete=true. Проверить отсутствие VM/диска в облаке. Снимки диска не создавать. Если работа прервана, при возобновлении сначала проверить таймер, статус VM и остаток бюджета.

Использование облачной Linux VM вместо исходного VirtualBox/Vagrant стенда нужно честно указать в отчёте.

Проверка завершена: Terraform fmt, validate и plan успешны; провайдер 0.240.0 зафиксирован в .terraform.lock.hcl. Реальный план содержит ровно 4 create, без update/delete. Полный план/SSH public key/адрес оператора не публикуются. Apply ожидает лимит расходов.
